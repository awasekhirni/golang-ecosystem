## Objectives

1. Detect regressions in latency, error rate, and availability.
2. Detect DB pool pressure and slow queries before they become incidents.
3. Detect domain-event handler failures before they cause data inconsistency.
4. Track delivery throughput (PR cycle time, deployment frequency).

## Metrics

| Metric | Source | Cadence | SPC baseline | Action limit |
|--------|--------|---------|--------------|--------------|
| `http_request_duration_seconds{p99}` | Prometheus | 1m rolling | 250ms | >500ms page |
| `http_requests_total{status=~"5.."}` rate | Prometheus | 1m | 0.1% | >1% page |
| `db_query_duration_seconds{p99}` | Prometheus | 5m | 50ms | >200ms warn |
| `bus_dispatch_errors_total` rate | Prometheus | 5m | 0 | >0 warn |
| `audit_events_total{action="DELETE"}` rate | Prometheus | 1h | 0 | investigate spike |
| Deployment frequency | CI | weekly | 5/wk | <2/wk investigate |
| PR cycle time (median) | GitHub | weekly | 4h | >24h investigate |

## Statistical Process Control (SPC)

Each baseline is computed from the trailing 30-day rolling mean and standard
deviation. A data point outside ±3σ triggers an Out-of-Control signal and
creates a CAR candidate (06). SPC baselines are recomputed on the 1st of each
month; the previous baseline is archived for trend analysis.

## Dashboards

- **Operational**: Grafana dashboard `hexagonal-go-ops` showing p50/p95/p99
  latency, 5xx rate, in-flight, DB pool stats, slow-query count.
- **Domain**: Grafana dashboard `hexagonal-go-domain` showing
  `domain_events_published_total` by topic, `audit_events_total` by action.
- **Delivery**: Grafana dashboard `hexagonal-go-delivery` showing deploy
  frequency and PR cycle time.
